# KCP Core Evidence/Execution Alpha - 1.0.0a0

## Summary

This is the first public alpha of the Klein Conformance Protocol evidence and verification stack.
It packages the current KCP core, DMF/EWOD simulator profile, trust/bundle/verifier machinery,
dry-run adapter skeletons, public demo assets, and whitepaper documentation into a release-candidate
state.

KCP is an evidence, conformance, and verification protocol stack for physical-substrate execution
attempts under uncertainty. This alpha verifies evidence artifacts and declared bindings. It does
not prove physical execution.

## What Works

- HAIL v1 event validation.
- Canonical JSON/JCS hashing for evidence and artifact binding.
- HAIL chain digests.
- Signed Run Manifest v1.
- Trust Policy v1.
- Backend Identity Registry v1.
- Signed registry provenance.
- Signed Backend Capability Declaration v1.
- Conformance Levels Matrix v1 catalog.
- `.kcprun` Run Bundle v1 packaging and verification.
- Python independent verifier.
- Rust verifier slice over cross-language fixtures and bundle checks.
- DMF/EWOD simulator profile alpha.
- `.klein` Project v1 and `.kleinc` Container v1 artifact schemas.
- Runbook v1 and Execution Trace v1.
- ECRP contract and one simulator-only recovery success path.
- Observation v1 simulator snapshots.
- HIL Readiness v1.
- Recorded Device Run v1.
- Generic DMF dry-run adapter.
- OpenDrop/EWOD dry-run adapter skeleton.
- OpenDrop Transport Planning v1 with disabled transport configs and deterministic dry-run command
  stream fixtures.
- Current-alpha OpenDrop schemas enforce the same no-hardware policy as runtime validators.
- Trusted Timestamp Profile v1 stub with mock/local timestamp profile and token validation.
- Attestation Profile v1 stub with none/mock attestation profile and statement validation.
- Public demo package under `examples/public-alpha/`.
- Whitepaper v1 at `docs/WHITEPAPER.md`.

## What Does Not Work / Non-Claims

This alpha does not claim:

- hardware support;
- HIL execution;
- physical truth proof;
- real OpenDrop control;
- OpenDrop serial hardware transport;
- sensor proof;
- trusted timestamp proof or external timestamp authority verification;
- hardware attestation proof, hardware identity proof, or TPM/TEE verification;
- production certification.

These are target or future claims tracked in the roadmap and claims ledger.

## Known Limitations

- The authoritative v1 suite is under `tests/vectors/v1`; the legacy corpus remains report-only.
- Current trust is local/test trust policy, not global PKI.
- Current observations are simulator-backed snapshots, not hardware sensor evidence.
- Current adapters are dry-run/mock skeletons, not hardware drivers.
- Current recorded runs are mock/dry-run archives with `hardware_claimed: false`.
- OpenDrop transport planning is independently written; KCP does not copy or vendor
  GaudiLabs/OpenDrop firmware or controller code. Future hardware integration requires license
  compatibility review before copying or deriving from GPL-licensed code.
- Future OpenDrop serial hardware transport requires a later schema/profile or explicit unsafe mode;
  the current alpha schema rejects active hardware configuration.
- Trusted timestamp proof and hardware attestation proof are not implemented; only mock/local
  timestamp profile/token and none/mock attestation profile/statement stub validation exists.
- `tests/fixtures/crypto/backend_test_ed25519_private.pem` is an intentional public deterministic
  test fixture key only, not a production signing or backend identity key.
